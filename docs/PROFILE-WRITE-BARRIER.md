# Profile writer origin barrier — 2026-10-15

Optional native SPI ProfileWriteBarrier.capture(UUID,PersistentDataKey<?>,Object) returns a complete fenced persistence task for an owned key, or null to retain the ordinary serializer for an unowned key. Capture is I/O-free and runs before EcoProfile's cache write, ProfileWriter coalescing and handler executor dispatch. Never recapture session/revision at flush/SQL time. A protected task replaces the serializer; wrapping a serializer that opens its own transaction would not share the fence.

PersistentDataHandler.prepareWrite/writePrepared preserve existing write/read public descriptors. Direct write and loadSerializedProfile also go through capture. PreparedProfileWrite is single-dispatch, exposes a read-only completion stage, and can be superseded by a newer coalesced value. Conditional coalescer removal preserves racing newer work. Installing an immutable barrier invalidates previously captured unguarded jobs rather than letting them bypass a fence. Never replace/remove a live binding; startup must reconcile/drain pre-binding work and admit owned mutations only after sessions/cache are ready.

The default path has no barrier. No registration or SQL/schema change is performed by adding these classes. Unrelated plugin serializers remain native. Consumers affected if a barrier is activated: EcoSkills (target), and all eco/LibreForge plugins using ordinary Profile writes; only actual registered owned EcoSkills keys may be intercepted. EcoArmor/EcoEnchants/EcoItems/Talismans/LibreForge must continue their unowned native paths. No NMS/toolchain/parser/API normalization.

FencedNativeProfileWriter in EcoSkills implements this SPI with one transaction for fence, ordering marker and registered INT/DOUBLE native value. Its presence does not make a provider ready: whole native operations still need queuing while a grant commits, original sessions need admission, and coherent loaded cache/holder publication must precede resuming writes. The initialized real MySQL backend is not bound by this increment. Do not expose this privileged SPI or SQL internals as observation access for web/bot.
